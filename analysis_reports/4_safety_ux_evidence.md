# F3-Win 与原版 F3 (Upstream) 系统安全隔离、设备识别、交互生态与司法存证对比深度分析报告

## 摘要

本报告针对闪存扩容盘检测工具领域中，本项目（F3-Win，基于 Rust 2021 + eframe/egui 0.29 + Win32 Native API）与原版 F3（Fight Flash Fraud，基于 Linux/macOS 纯 C 命令行套件）在**宿主介质安全隔离与防呆体系**、**架构交互形态与工程交付**、**测速生理学分析与颗粒体质推断**以及**司法维权存证与证据保护**四个核心维度展开系统的源码级对比分析。

分析表明，原版 F3 受限于历史 Unix CLI 工具设计范式，缺乏对现代存储总线拓扑的识别能力与宿主系统防御机制，在易用性、硬件推断深度以及消费者维权存证链路上存在显著的工程代差。F3-Win 在继承原版算法有效内核的基础上，通过 Win32 Direct I/O、总线白名单防御、在线非参数统计测速、微观病理推断与司法级固证链路，构建了面向现代 Windows 桌面环境的高安全性、高可用性闪存检测全栈闭环。

## 二、 宿主介质安全隔离与防呆体系深度对比

### 1. 原版 F3 的宿主安全隐患与缺陷

在原版 F3 的设计中，程序输入完全依赖命令行传入的路径字符串或原始块设备节点名：

```c
// .upstream_f3/src/f3probe.c: main()
dev = args->debug
    ? create_file_device(...)
    : create_block_device(args->filename, RT_NONE);
```

#### 关键缺陷剖析：
1. **零总线拓扑感知与白名单校验缺失**：
   原版程序通过 `open(argv[x], O_RDWR | O_DIRECT)` 直接打开目标设备节点。程序无法区分传入的设备到底是外接 USB 闪存盘，还是宿主机的内部固定 SATA 机械硬盘或 NVMe 系统固态硬盘。
2. **缺乏系统引导盘硬隔离防护**：
   在 Linux 环境下，系统主盘通常分配为 `/dev/sda`，而外接移动设备通常为 `/dev/sdb` 或 `/dev/sdc`。由于 `f3probe --destructive` 必须以 root（超级管理员）权限运行，一旦普通用户输入错误（如将 `/dev/sdb` 误敲为 `/dev/sda`），程序将毫无阻拦地直接对主机系统主盘的物理 LBA 扇区（包括 LBA 0 处的 MBR / GPT 分区表与引导代码）执行高频覆写探针，引发灾难性的系统崩溃与全盘数据抹除。
3. **缺乏底层卷独占锁定与卸载保护**：
   原版在操作块设备前，仅依赖用户在操作系统外部手动执行 `umount`。若卷处于挂载状态或存在后台文件读写，直接并发执行底层块写入将导致文件系统元数据损毁与内核脏页回写竞态冲突。
4. **缺乏操作前防呆与二次风险确认**：
   在 CLI 模式下，只要附加 `--destructive` 参数并按下回车，程序便立即向目标物理裸盘执行破坏性探针，没有运行时的可回退确认交互界面。

### 2. 本项目 (F3-Win) 的设备安全中枢与多层防御体系

F3-Win 在 `src/core/devices.rs` 中构建了完整的操作系统级硬件安全防护中枢，实现了多重软硬件隔离闭环：

```
+--------------------------------------------------------------------------+
|                     F3-Win 物理存储安全防御中枢                          |
+--------------------------------------------------------------------------+
|  [硬件属性探测] IOCTL_STORAGE_QUERY_PROPERTY -> BusType                   |
|       |                                                                  |
|       +--> USB (7) / SD (12) / MMC (13) / 外置 NVMe -> 白名单放行        |
|       +--> SATA (11) / 内部 NVMe (17) / ATAPI / RAID -> 绝对硬隔离锁定  |
|                                                                          |
|  [系统引导盘智能反查] %SystemDrive% -> C: -> IOCTL 反查 Disk Number      |
|       |                                                                  |
|       +--> PhysicalDrive0 / 系统盘索引 -> 无论总线类型，实施绝对阻断     |
|                                                                          |
|  [Zero-TOCTOU 现场复核] 破坏性操作前一刻重新查询硬件总线 (防插拔漂移)    |
|                                                                          |
|  [卷独占锁定闭环] FSCTL_LOCK_VOLUME (3次退避) + FSCTL_DISMOUNT_VOLUME    |
|       |                                                                  |
|       +--> RAII 守卫 VolumeLockGuard 确保退出/异常时自动关闭句柄恢复挂载 |
|                                                                          |
|  [UI 界面层强制防呆] 常驻风险须知卡片 + 显式复选框确认 + 按钮置灰保护     |
+--------------------------------------------------------------------------+
```

#### 核心防御技术机制：
1. **基于 IOCTL_STORAGE_QUERY_PROPERTY 的总线白名单防御**：
   程序在枚举设备与打开目标前，向设备句柄下发 `IOCTL_STORAGE_QUERY_PROPERTY` 查询 `STORAGE_DEVICE_DESCRIPTOR`，提取底层硬件总线类型 `BusType`：
   - 白名单仅允许：`StorageBusType::Usb` (7)、`StorageBusType::Sd` (12)、`StorageBusType::Mmc` (13)，以及明确标记为 `RemovableMedia = true` 的外置 USB4 / 雷电移动固态硬盘；
   - 内部固定介质绝对锁定：所有 `StorageBusType::Sata` (11)、内部固定 `StorageBusType::Nvme` (17)、ATAPI 与未知总线介质，在识别层直接标记 `is_safe_target = false`，UI 层强制置灰并锁定。
2. **系统引导盘 (%SystemDrive%) 动态智能反查与硬隔离**：
   系统通过环境变量 `SystemDrive`（优先，备选 SystemRoot/windir，兜底 'C'）提取当前 Windows 操作系统引导盘符；进一步通过 `IOCTL_STORAGE_GET_DEVICE_NUMBER` 动态解析出该逻辑卷所挂载的底层物理磁盘索引号（通常为 `PhysicalDrive0` 或对应系统盘索引）。
   - 规则：任何位于系统主盘（索引等于 0 或系统引导盘索引）的设备，或挂载了 `C:` 卷的存储目标，一律强制阻断破坏性物理操作，彻底杜绝误选系统盘的可能性。
3. **Zero-TOCTOU（检查到使用时间差）零时差现场复核**：
   在用户点击开始探测与底层驱动执行物理写入之间的临界时刻，`StorageTarget::prepare_for_probe` 会调用 `PhysicalDeviceInfo::query_by_index` 重新现场核验物理磁盘的硬件属性。即使发生高速拔插导致的物理磁盘编号重分配，一旦发现目标变为非移动介质或系统盘，立即中止并抛出错误。
4. **FSCTL_LOCK_VOLUME 与 FSCTL_DISMOUNT_VOLUME 卷独占锁定闭环**：
   在物理跳跃探测启动前，程序遍历该物理磁盘上映射的所有逻辑卷，向各卷句柄下发 `FSCTL_LOCK_VOLUME` 实施独占锁定，并下发 `FSCTL_DISMOUNT_VOLUME` 卸载文件系统。
   - 内置 3 次退避重试（间隔 100ms），吸收 Windows Search 索引器或杀毒软件的瞬时读占用；
   - 采用 RAII 资源管理机制：句柄由 `VolumeLockGuard` 接管，在结构体析构（Drop）时自动调用 `CloseHandle`，确保无论探测成功、中途中止还是异常崩溃，Windows 均能安全释放锁并自动恢复卷挂载。
5. **闪电探测常驻安全须知与显式复选框强制防呆**：
   在 GUI「闪电探测」标签页顶部，设计了常驻的数据安全告示卡片，明确告知物理扇区覆写机制以及测试完毕后必须格式化的事实；设计了强制交互复选框：
   ```rust
   // src/gui/app.rs
   ui.checkbox(
       &mut self.state.probe_backup_confirmed,
       RichText::new("我已确认备份 U 盘内的所有重要文件，并知晓测试完毕后需要重新格式化 U 盘")
   );
   ```
   若用户未显式勾选，主操作按钮将持续显示「请先勾选确认安全须知」并保持不可点击置灰状态；即便绕过 UI，底层 `start_probe` 入口也配置了强制校验断言，实现双层防御。

## 四、 测速生理学分析与颗粒体质推断对比

### 1. 原版 F3 的测速局限

在原版 F3 (`f3write.c` / `f3read.c`) 中，速率统计采用粗粒度的累计平均算法：

```c
// .upstream_f3/src/f3write.c
print_avg_seq_speed(&fw, "write", true);
```

#### 局限性：
- 仅在读写完成时打印 `Average writing/reading speed`；
- 无法排除操作系统页面缓存（Page Cache）在刚启动时的虚高突发；
- 无法捕捉现代 3D NAND 闪存具有的动态 SLC Cache 写入缓冲机制，无法获知缓外真实直写速率；
- 无法给出任何关于硬件物理总线是否饱和、颗粒属于正品还是黑片的实质性推断。

---

### 2. F3-Win 测速生理学引擎与颗粒体质推断

F3-Win 在 `src/core/speed.rs` 与 `src/core/report.rs` 中引入了存储物理微观生理学分析模型，突破了传统工具单纯汇报数字的局限：

```
+--------------------------------------------------------------------------+
|                     F3-Win 存储生理学分析流水线                          |
+--------------------------------------------------------------------------+
|  [冷启动过滤] 预热阈值 32MB / 3次采样 -> 剔除初段模拟缓存瞬态毛刺       |
|       |                                                                  |
|  [流式统计计算] Welford 增量均值与方差 -> 变异系数 (CV Jitter)           |
|       |                                                                  |
|  [相继差抖动] RMSSD 连续采样差分均方根 -> 测定总线锯齿波动剧烈度         |
|       |                                                                  |
|  [P² 在线中位数分位数估算] 80 字节 O(1) 空间逼近稳态中位速度             |
|       |                                                                  |
|  [SLC 断崖状态机] 连续 3 周期 40% 掉速防抖滤波 -> 锁定真实物理缓外边界   |
|       |                                                                  |
|  +---------------------------+    +-----------------------------------+  |
|  |   7 阶梯物理总线推断      |    |       6 级闪存颗粒体质推断        |  |
|  | - USB 1.1 / 2.0 / 3.2 / 4 |    | - Grade S (企业级 / 高阶NVMe)     |  |
|  | - Thunderbolt 3/4/5       |    | - Grade A (原厂高良率 Good Die)   |  |
|  | - SD 1.01 ~ SD Express    |    | - Grade B (主流商业级 3D TLC)     |  |
|  |                           |    | - Grade C (降级次品白片/QLC)      |  |
|  |                           |    | - Grade D (深度残次片/拆机Ink Die)|  |
|  |                           |    | - Grade F (报废黑片/漏电下脚料)   |  |
|  +---------------------------+    +-----------------------------------+  |
+--------------------------------------------------------------------------+
```

#### 核心算法与推断机制：
1. **冷启动预热过滤 (Cold-Start Warmup Filter)**：
   设置 32MB 或连续 3 个采样周期的预热缓冲区，在刚启动阶段不更新谷底速度，有效消除系统启动与物理主控缓存初始化时的异常高噪点。
2. **Welford 增量均值与方差算法**：
   采用数值稳定的单趟递推算法在线维护均值与方差，实时输出传输速率变异系数（CV Jitter，标准差与均值之比），数学化度量传输稳定性。
3. **相继差均方根 (RMSSD) 与卡顿比率 (Stall Ratio)**：
   计算相邻两次采样差值的均方根，精确度量速度曲线的微观剧烈抖动；统计瞬时速度低于 1.0 MB/s 的采样占比，量化主控总线卡死程度。
4. **P² (Piecewise-Parabolic) 分位数在线估算器**：
   闪存测试往往耗时数十分钟甚至数小时，传统的全量数组排序中位数算法会无上限消耗内存。F3-Win 实现了 P² 分位数估算器：
   - 内存固定开销仅 80 字节，时间复杂度 O(1)；
   - 无需在内存中保存任何历史测速样本数组，即可高精度逼近真正的稳态中位数速度（Median Speed），从根本上避免单次偶发冲顶扭曲整体评估。
5. **SLC 断崖特征探测状态机 (SLC Cliff Detection State Machine)**：
   主控模拟 SLC 缓存耗尽时通常伴随速度断崖式暴跌。状态机在进入 `InBurst` 阶段后锚定峰值速率；当速度跌落至峰值的 40% 以下时，进入 `SuspectedCliff` 状态；只有当**连续 3 个采样周期**均维持在 40% 低位时，才正式判定为 SLC 耗尽断崖成立。该防抖设计彻底消除了系统后台读写引发的单次虚假掉速误报。
6. **7 阶梯物理总线规格动态推断**：
   结合设备的硬件总线标识与实测峰值/中位速度，动态反推介质实际连接的物理信道协议：
   - USB 阶梯：USB 1.1 Full-Speed (<1.5 MB/s)、USB 2.0 High-Speed (<43.5 MB/s)、USB 3.2 Gen 1x1 5Gbps (<450 MB/s)、USB 3.2 Gen 2x1 10Gbps (<1050 MB/s)、USB 3.2 Gen 2x2 20Gbps (<2050 MB/s)、USB4 Gen 3x2 / Thunderbolt 3/4 (<3800 MB/s)、USB4 2.0 / Thunderbolt 5 (超高速 PAM3)；
   - SD 阶梯：SD 1.01 (<12.5 MB/s)、SD 1.10 (<25 MB/s)、UHS-I SDR50 (<50 MB/s)、UHS-I SDR104 (<104 MB/s)、UHS-II (<312 MB/s)、UHS-III (<624 MB/s)、SD Express (最高可达 3940 MB/s)。
7. **6 级闪存颗粒体质与微观病理解析**：
   基于稳态中位与平均速度，对物理颗粒的晶圆品质进行分级推断：
   - **Grade S** (>=80 MB/s)：企业级 / 高阶 PCIe NVMe 闪存，配备独立硬件 DRAM 缓存，高负载平稳不掉速；
   - **Grade A** (25~80 MB/s)：原厂高良率 Good Die / eMMC 5.1 / UFS 级颗粒，具备多 Die 多通道并行交错读写能力；
   - **Grade B** (8~25 MB/s)：常规合格商业级 3D TLC 原厂白片，消费级主流体质；
   - **Grade C** (3~8 MB/s)：降级次品白片 / 3D QLC 边缘晶圆次品，单 Die 单通道，出 SLC 缓存后直写极低；
   - **Grade D** (1~3 MB/s)：深度降级 TLC 晶圆残次片 / 二手翻新拆机片 Ink Die，未通过原厂品控，擦写寿命极短；
   - **Grade F** (<1 MB/s)：极度报废黑片 / 严重漏电下脚料 / 报废 TF 废旧打胶封装芯片，绝缘层破损，电荷极速泄露。
   - **微观病理解析**：自动在报告中解析假盘在垃圾回收（Garbage Collection, GC）时物理块擦除锁定（tBERS 典型耗时 2~5 ms）导致的主控算力死锁与传输阻塞特征。

## 四、 司法维权存证与证据保护对比

### 1. 原版 F3 的维权证据断裂

在维权与存证能力上，原版 F3 存在致命的证据链断裂缺陷：
1. **测试结果非标准化**：仅在终端输出简短文本，缺少测试环境、硬件哈希指纹、测试时间戳等法律公信要素；
2. **无介质唯一物理身份锚定**：输出不包含物理卷序列号（Volume Serial Number）与设备物理硬件标识，在司法争议或电商仲裁中，商家极易辩称“消费者自行拿别的损坏盘调包检验”，导致证据被全盘推翻；
3. **破坏性文件清理建议**：原版 F3 官方 README 及常规工作流中，甚至直接指导用户在测试后执行 `rm -rf /path/*.h2w`。一旦删除了测试文件，物理介质上的真实覆写现场即被完全销毁，司法鉴定机构将无法对物理扇区展开二次复核鉴定。

---

### 2. 本项目 (F3-Win) 的司法级存证中枢与证据保护守卫

F3-Win 在 `src/core/session.rs`、`src/core/report.rs` 及 `src/gui/app.rs` 中构建了完整的法律维权证据链闭环：

```
|       |                                                                  |
|       +--> 检测条件: bad > 0 || overwritten > 0 || changed > 0           |
|       +--> 动作: 绝对拦截删除测试文件！强行锁定物理现场 .h2w 实物证据    |
|       +--> 放行条件: 仅当 100% 全绿正品盘时，才允许后台无感清理          |
|                                                                          |
|  [微观比特失配现场提取] (report.rs)                                       |
|       |                                                                  |
|       +--> 捕获首发错误绝对物理偏移量、所属分卷编号                      |

|       |                                                                  |

|       +--> 支持导出标准 Markdown (.md) 与 ASCII PlainText (.txt) 到桌面  |
|       +--> 原生 Win+Shift+S 公文卡片一键截屏存证                         |
+--------------------------------------------------------------------------+
```

#### 核心存证能力剖析：
1. **证据保护守卫 (Evidence Protection Guard)**：
   在 `src/core/session.rs` 的测试完成收尾逻辑中，设立了强制拦截断言：
   ```rust
   // 防伪维权保护守卫：只有在 100% 全绿正品盘时才允许自动清理！
   if self.config.auto_cleanup && stats.bad == 0 && stats.overwritten == 0 && stats.changed == 0 {
       // 执行安全清理
       let _ = Self::cleanup_h2w_files(&self.config.target_dir);
   }
   ```
   一旦检测到哪怕 1 个损坏扇区或回绕覆写扇区，系统立即彻底拦截清理动作，强行将写满伪随机数据的 `.h2w` 分卷完整保留在物理闪存介质上，保全实物证据，供公证处或司法鉴定机构随时提取检材。
2. **首发失配现场微观 Hexdump 对照**：
   在读取校验到首个错误块时，系统自动锁定该错误扇区的绝对字节偏移量（例如 `0x00000001F4000000`，7.81 GB 处）及其所在的分卷编号，并提取 16 字节预期数据与实际读回数据的 Hex 对照表：
   - 预期数据（Expected）：基于加盐 PRF 生成的确定性伪随机序列；
   - 实际数据（Actual）：如全 `0x00`（位黑洞丢弃）、全 `0xFF`（未初始化或虚假映射）或盘首重放数据（主控地址线回绕覆写）；
   - 该微观对比直接排除了“软件偶然读取错误”，从硬件层铁证化主控固件的欺诈篡改行为。
3. **介质唯一身份指纹全息锚定（彻底杜绝调包抗辩）**：
   生成的公文案卷中，全息记录：
   - 32 位物理卷序列号（Volume Serial Number，十六进制格式如 `0xABCD1234`）：该序列号由操作系统在格式化时生成，无法由用户轻易伪造，彻底封死不法商家在仲裁时辩称“买家调包退货”的借口；
   - 硬件级总线与身份标识：BusType、VendorId、ProductId、硬件序列号；
   - 测试方法学标准声明： Win32 Direct I/O（FILE_FLAG_NO_BUFFERING | FILE_FLAG_WRITE_THROUGH）逐扇区测试，符合国家司法鉴定规范认可的物理直通测试标准。
4. **符合《消费者权益保护法》第 55 条法定索赔主张书**：
   在 `src/core/report.rs` 中，自动嵌入了面向平台仲裁客服、消协或人民法院的标准公函文本：
   - 援引《中华人民共和国民法典》第一百四十八条（欺诈民事行为的撤销）；
   - 援引《中华人民共和国消费者权益保护法》第五十五条第一款规定（“退一赔三，增加赔偿的金额不足五百元的，为五百元”）；
   - 列明标称容量、实测可用容量、虚假扩容比例、首次失配物理偏移量与诉求清单；
   - 支持一键导出到桌面（Markdown / 纯文本带 ASCII 表格）、一键复制到剪贴板，并在 GUI 界面中提供支持 Windows 快捷键（Win + Shift + S）一键截屏的司法鉴定级公文卡片。

## 六、 结论与工程演进展望

F3-Win 不仅是对原版 F3 检测算法在 Windows 平台上的高性能 Direct I/O 重构，更是在**宿主介质安全防御**、**现代工业级 GUI 交互**、**闪存微观生理学推断**与**消费者权益保护法存证闭环**上实现的全面代际跃迁。

1. **在安全防御上**：彻底根除了原版 F3 命令行在多盘环境下极易误伤系统引导盘的毁灭性风险，为普通消费者与工程人员筑牢了物理级硬隔离防线；
2. **在交互交付上**：以现代极简直角黑白工业设计系统与单文件免安装形态，将晦涩的底层硬件诊断转化为直观、防抖、优雅的可视化操作体验；
3. **在深度诊断上**：以在线非参数中位数与生理测速状态机，穿透黑产假盘前端的 SLC 模拟缓存伪装，直击闪存颗粒的真实物理体质；
4. **在法律维权上**：通过证据保护守卫与司法鉴定案卷，填补了开源闪存检测工具长期以来“测出假盘却无法律效力证据”的空白，为维护公平的消费市场秩序提供了坚实的工程技术底座。
