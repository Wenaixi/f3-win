# FlashGuard-Win (F3-Win)

面向物理闪存存储介质的真伪鉴别与安全自愈系统。

基于现代系统级语言 Rust 与 Win32 原生 Direct I/O 架构打造，具备底层文件系统缓存绕过、双通道不可逆非线性雪崩防伪加盐、双向对流跳跃二分探针、写入与读取速率平滑分析，以及存储设备白名单安全自愈能力。单文件绿色免安装，专为终结假盘黑产、守护数据安全而生。

---

## 一、研发背景与行业现状

随着固态闪存技术的普及，移动固态硬盘（PSSD）、高速 U 盘与 TF/SD 卡已成为广大师生、科研人员与普通消费者存储课件、实验数据及核心资产的重要工具。

然而，电商平台与消费市场长期充斥着大量经过固件篡改的“虚标扩容假盘”。不良厂商通过量产工具修改闪存控制器固件中的分区与容量配置（例如将 8GB 或 16GB 的残次劣质颗粒伪报为 512GB 甚至 2TB），并施加微码欺骗。用户在初期写入时往往无异常感知，但一旦写入数据超出真实物理颗粒界限，控制器便会触发物理地址回绕（Wrap-around）静默覆盖前序扇区，或直接将数据重定向至只写不存的“位黑洞”（Bit-Bucket），导致用户的关键数据发生永久性、不可逆的损毁。

### 传统检测工具的历史局限性

在过去十余年间，业界主要依靠早期 Linux 命令行脚本（如 2010 年代初期的 F3 脚本）或老旧的 Windows 第三方工具（如基于 Win32 标准文件 API 的 H2testw）进行校验。面对当代黑产固件的技术升级，传统工具暴露出明显的时代局限性：

| 评估维度 | 传统工具（H2testw / 早期 F3 脚本） | FlashGuard-Win (本系统) | 技术突破与优势 |
| :--- | :--- | :--- | :--- |
| **运行平台** | 依赖 Linux 终端命令或过时 32 位环境 | Windows 10/11 原生原生支持（x64 & ARM64） | 纯原生系统级适配，提供现代直角黑白工业 GUI |
| **I/O 驱动机制** | 依赖系统标准文件缓存，受内存缓冲干扰 | Win32 Direct I/O (`NO_BUFFERING | WRITE_THROUGH`) | 彻底绕过系统文件缓存，直达闪存物理裸盘 |
| **抗固件作弊能力** | 纯线性同余生成器，代数可逆，易被固件算力回放绕过 | 双通道不可逆非线性雪崩 PRF 动态加盐置换 | 固件无法推导密钥，从信息论上强制真实落盘 |
| **容量探测耗时** | 需全盘写满校验，数百 GB 往往需要耗费几个小时 | 双向对流跳跃二分探针，一般几分钟内即可完成 | 大幅缩短排查时间，迅速查明真实物理边界 |
| **探针盲区防御** | 仅单向探针，易被位黑洞假盘（读全0/全FF）欺骗 | 高位专属探针 + 32MB 深度冲刷 + 双基准回读 | 彻底消灭位黑洞与非 2 次幂模回绕漏报漏洞 |
| **扇区健康感知** | 仅输出孤立的损坏字节数字统计 | 1000 采样点光刻晶圆级四态热力图矩阵 | 直观渲染 Good / Bad / Changed / Overwritten 状态 |
| **存储自愈能力** | 仅报警检测结果，无法修复，需用户手动分区 | 事务型白名单自愈，防呆规避系统盘，一键恢复可用分区 | 自动计算物理安全边界并调用底层引擎无损重建 |
| **测速与介质推断** | 简易粗糙的时长平均值，无法反映颗粒真实体质 | Welford 流式方差 + P² 分位数 + 物理总线 7 阶梯推断 | 精准捕捉 SLC Cache 耗尽断崖与颗粒体质评级 |

## 二、核心架构与五大技术支柱

FlashGuard-Win 采用系统级高可靠性架构设计，不依赖任何第三方运行时环境或 C++ 动态链接库，由五大技术底座协同运作：

### 1. Win32 Direct I/O 原生硬件直通底座
- **无缓冲穿透机制**：通过 Win32 原生 API `CreateFileW` 配置 `FILE_FLAG_NO_BUFFERING | FILE_FLAG_WRITE_THROUGH` 标志位，彻底切断 Windows 系统级文件缓存（Page Cache）的干扰，使每一次 I/O 请求直接作用于物理硬件介质；
- **物理扇区硬对齐**：使用底层系统调用分配 4KB 物理扇区对齐的环形多级缓冲区，针对 512B 传统扇区与 4Kn 物理大扇区进行自适应适配；
- **强制穿透冲刷**：写入完成与写满截断时下发 `FlushFileBuffers`，向闪存控制器强制注入 SCSI SYNCHRONIZE CACHE / NVMe Flush 指令，排空主控 Write-Back 缓存与 FTL 映射表，避免突发拔盘导致的数据丢失与假阳性判定。

### 2. 抵御固件算力回放的不可逆雪崩加盐 PRF
- **漏洞根因破解**：传统工具所采用的线性同余 PRNG（乘数 4294967311，增量 17）在模 2^64 下具有唯一的代数模逆元。现代黑产恶意固件通过扇区首部的明文偏移量与首个随机数，仅需一次简单的代数乘加运算就能顺带反解出密钥，进而在控制器高速缓存内实施“只读即算、0 字节物理闪存”的算力回放欺骗；
- **双通道雪崩置换算法**：FlashGuard-Win 自主设计了 `one_way_seed` 非线性双通道雪崩置换函数，结合多步非线性异或位移运算与动态随机盐（Salt）。在密码学意义上打破了代数可逆性，使恶意固件在没有私钥的情况下无法在写入阶段实时反解密钥，从信息论上强制控制器必须将数据真实持久化至物理颗粒中；
- **双模兼容生态**：在 Salt = 0 默认模式下保持与传统标准的 100% 逐比特二进制向后兼容；开启安全加盐后即刻激活抗黑产固件欺骗防御。

### 3. 双向对流跳跃二分探针体系
- **双基准扇区协同**：避开易受固件静态欺骗的 LBA 0 引导区，在 LBA 2048 (1MB) 与 LBA 4096 (2MB) 双锚点写入基准探针；
- **32MB 深度缓存穿透**：探针写入后动态执行 `overwhelm_cache`，深度冲刷 32MB 高熵白噪声数据，物理击穿现代移动介质内置的 SLC 模拟缓存与主控 SRAM；
- **双向对流闭环核验**：
  - 动作一（高位读回）：校验高位目标扇区数据，若读取成功但数据被篡改或清零，精准判定为【位黑洞欺骗】；
  - 动作二（低位回读）：反向回读 LBA 2048/4096 基准扇区，若基准数据被新探针冲刷覆盖，精准判定为【硬件地址回绕】；
- **Phase 1 指数粗测 + Phase 2 二分逼近**：以 28 级双倍几何阶梯实现最高 8TB 存储介质的快速粗测，随后利用二分逼近搜索将真实物理容量的定性收敛误差缩减至 1MB 级。

### 4. 动态测速波动分析与闪存颗粒体质推断
- **流式统计引擎**：在每次物理块读写间隙顺带计算，采用 Welford 流式方差与 P² 在线分位数算法，既不拖慢读写速度，又无需占用额外内存，就能准确算出稳态中间速度与波动幅度；
- **SLC 耗尽状态机**：三阶段自适应捕捉闪存颗粒从“高速模拟 SLC 缓存”跌入“颗粒原生 TLC/QLC 慢速直写”的物理断崖拐点；
- **物理总线与颗粒体质 7 阶梯矩阵**：依据实测峰值与中位速率，客观推断 USB 物理通道（USB 1.1 至 USB4/雷电）与 NAND 颗粒体质（Grade F 报废黑片至 Grade S 企业级原厂颗粒），并分析 FTL 重构与垃圾回收（GC）锁定病理。

### 5. 安全分区自愈与司法维权存证
- **Fail-Close 物理安全防御**：底层通过 `IOCTL_STORAGE_QUERY_PROPERTY` 穿透查询总线类型，严格白名单锁定移动介质（USB / SD / MMC），对本地系统引导盘（%SystemDrive% 及 PhysicalDrive0）实施绝对物理隔离与一票否决；
- **RAII 卷排他锁生命周期**：封装 `VolumeLockGuard`，在底层底层探测期间独占锁定卷挂载，任务结束、异常中断或掉盘时自动恢复；
- **一键分区自愈**：一键生成纯 ASCII、免疫区域代码页乱码的标准 `diskpart` 事务脚本，以真实物理安全容量重写 MBR/GPT 分区表并格式化，让假盘变身为容量真实、数据不丢的安全可用盘；
- **法定存证公文卡片**：一旦捕获到损坏（Bad）或覆盖（Overwritten）扇区，系统自动提取首发错误扇区 Hexdump 对照，生成具备公文相框质感的高对比度检验结论书，支持系统快捷键 `Win + Shift + S` 截屏，作为依据《消费者权益保护法》第五十五条“退一赔三”的维权铁证。

## 三、用户界面与交互设计

FlashGuard-Win 确立了**现代深空黑白极简工业设计系统（Deep Monochrome Design System）**：

- **零外部 UI 依赖**：基于纯原生 Rust GUI 引擎构建，不依赖 Node.js、Electron 或 Chromium，启动迅速无等待感，运行时内存占用仅约 30MB；
- **纯粹直角工业风**：全面摒弃花哨圆角，采用工业级 1px 发丝分割线与高对比度反白字阶梯，控件焦点满足 WCAG 2.1 AA 7.2:1 超高对比度无障碍标准；
- **Bento-Grid 四卡片看板**：70px 工业级固定高度卡片，呈现读写瞬时速率、已处理字节、动态精准 ETA 倒计时与综合质量评级，消除数据周期刷新引起的界面抖动；
- **半导体光刻晶圆热力图**：1000 单元格保持 4:3 黄金网格比例，实时动态自适应渲染各扇区物理状态；
- **原生 Win32 系统托盘中枢**：利用 Windows 底层隐形消息窗口与异步管道，支持后台静默测试、500ms 降频节能与资源管理器重启自愈（TaskbarCreated）。

## 五、运行与构建指南

### 1. 直接运行（面向最终用户与评委）

- **支持系统**：Windows 10 / Windows 11（支持主流 x86_64 与 ARM64 设备）；
- **运行方式**：直接双击运行 `f3-win.exe` 单文件绿色程序（体积仅约 3.4MB）；
- **权限说明**：程序自带 `requireAdministrator` 清单，启动时若未以管理员运行，会自动拉起系统 UAC 对话框完成提权，以确保具备访问底层物理裸盘与卷独占锁的安全权限。

### 2. 源码构建与离线单元测试（面向开发者与技术审查）

#### 环境准备
- 安装 Rust 稳定版工具链（2021 Edition 或更高版本）：
  ```bash
  rustup default stable
  rustup target add x86_64-pc-windows-msvc
  ```

#### 本地离线测试运行
本项目内置了基于内存模拟块设备（`MemoryBlockDevice`）的深度仿真测试套件，涵盖 PRNG 序列、SIMD 比对、物理回绕、位黑洞假盘、缓存排空窗口及状态机生命周期。无需插入真实物理设备或提权即可执行全量测试：

```bash
# 运行全部 36 项核心单元测试（严格断言全绿通过）
cargo test --all-targets
```

#### 自动化构建与代码门禁
本项目遵循严格的工业级编译与质量门禁规范：
```bash
# 静态代码检查（零警告门禁）
cargo clippy --all-targets -- -D warnings

# 发布版本本地构建（开启 LTO 与符号剥离）
cargo build --release
```

所有的正式发布产物均通过 GitHub Actions CI/CD 流水线，在纯净云端虚拟化矩阵中由自动化工作流完成静态安全审计、单元测试覆盖与跨架构制品打包。
